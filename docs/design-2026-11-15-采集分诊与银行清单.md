# 设计说明 · 采集分诊、补正重试与银行清单（2026-11-15）

## 1. 背景与问题

新接入门店把楼层、面积写进标题，也会发来「价格面议」、待核实面积。现状下：

1. 归一失败的挂牌（`area_num=None`、`price_num=None`、小区/户型无法解析）仍进入
   `entity_resolution.resolve`：面积为空拿不到 block key 的会沦为孤立单成员簇，
   价格为空的以 `price_close=0` 参与打分，缺项会把相邻户型串成一套；
2. 采集没有「完整 / 待补 / 不合规」的区分，整批退回后估价师看不出谁被拦；
3. 补正后没有重新处理的入口，同批重试可能产生重复记录，补正失败还有丢记录的风险；
4. 银行清单（导出 CSV）只按表导出，会带出未完成（待补）与已撤回（`off_market`）房源，
   且没有标注覆盖范围与待补数量。

## 2. 设计目标（对应验收口径）

- 采集分清 **完整（complete）/ 待补（incomplete）/ 不合规（invalid）** 三类，原文全部留档；
- **只有足以支持归并的记录进入房源簇**：待补、不合规、已撤回记录一律不参与算法 A/B；
- 补正后可重新处理；**同批重试不新增记录**（自然键 upsert）；补正失败不丢记录（补正走
  独立事务，校验失败只回滚本次修改）；未变化数据保持稳定（确定性、簇键不变）；
- 银行清单标出 **覆盖范围与待补数量**，且不出现未完成或已撤回房源。

## 3. 数据模型变更

### 3.1 `listings` 新增列（`models/listing.py`）

| 列 | 类型 | 含义 |
| --- | --- | --- |
| `ingest_stage` | str(20)，默认 `complete`，索引 | 采集分诊：`complete / incomplete / invalid` |
| `defect_flags` | JSON list | 阻断入簇的缺项标记（`area_missing`、`price_missing`、`community_missing`、`layout_missing`、`area_out_of_range`、`layout_unparsed` …） |
| `ingest_batch` | str(60)，索引、可空 | 采集批次号（同批重试携带同一批次号，幂等不新增） |
| `raw_payload` | JSON | 采集原文全量快照（七个原文列 + 标题 + 批次），保证原文留档不依赖后续修改 |
| `withdrawn_at` | DateTime，可空，索引 | 撤回时间；置位即从后续归并与银行清单剔除 |

历史库由 `Base.metadata.create_all` 自动建新表；对已存在表新增列由启动时
`src/config/app.py` 调用的轻量迁移 `ensure_schema()` 补齐（`INFORMATION_SCHEMA` 判列，
MySQL / SQLite 通用，不引入 Alembic）。

### 3.2 新表 `ingest_batches`（采集批次台账，`models/ingest_batch.py`）

| 列 | 含义 |
| --- | --- |
| `batch_no` 唯一键 | 批次号，自然键，重试复用 |
| `agency_id` / `agency_code` | 来源渠道（冗余 code 便于留档） |
| `status` | `received / processed / failed` |
| `received_count / complete_count / incomplete_count / invalid_count / created_count / updated_count / unchanged_count` | 本批计数 |
| `retry_of` | 上一批次号（补正重试链） |
| `submitted_by / note / last_error` | 提交人与失败原因（失败不吞记录） |
| `processed_at` 及时间戳 | 可追溯 |

### 3.3 新表 `listing_corrections`（补正留痕，`models/listing_correction.py`）

每次补正一条挂牌生成一行：`listing_id`、`batch_no`、`field`、`before`、`after`、
`submitted_by`、`status(`applied / rejected`)`、`reason`。原文列被修改时先留痕，
`raw_payload` 永不覆盖。

## 4. 采集分诊规则（纯函数，`services/intake_service.py`）

`classify_listing(norm, raw) -> (stage, defect_flags)`：

- **invalid（不合规）**：`community_missing`、`layout_missing/unparsed`、`area_out_of_range`
  —— 关键身份字段缺失或越界，无法定位房源；
- **incomplete（待补）**：`area_missing`、`price_missing` —— 房源可定位但归并关键字段缺
  （价格面议、面积待核实即落此档）；
- **complete（完整）**：其余全部。

阻断入簇的硬条件（`can_merge(listing)`）：
`stage == "complete"` 且 `status == "active"` 且 `withdrawn_at IS NULL`。

## 5. 流水线改造（`services/pipeline_service.py`）

1. 全表刷新归一结果（原文不动），重算 `ingest_stage / defect_flags`；
2. 仅对 `can_merge` 的记录构造输入序列调用 `entity_resolution.resolve`；
   待补/不合规/已撤回记录 `property_id=NULL`、`risk_tags=[]`，不产生簇；
3. 风险扫描只看簇内在售完整记录；
4. 孤立完整记录仍按原口径生成单成员簇（保持 386 簇基准的可演化性）；
5. 旧簇裁剪逻辑保留（有复核单的簇不删）；
6. `MatchRun.metrics` 增加 `complete / incomplete / invalid / excluded / readmitted` 计数，
   日志逐行说明谁被拦、补正后谁重新入列，估价师在运行历史里可直接看到。

### 稳定性保证

- 归并算法本身未改：同一份完整记录输入，簇成员、`cluster_key`、golden record 与改造前
  逐字一致（`test_seed_dataset` 口径保持）；
- 待补记录补正为完整后，只是把该记录加入确定性输入序列，不改变其它记录的相对顺序与结果；
- 批次 upsert 以 `(agency_id, lid)` 为自然键：存在即更新（并记 `updated`），不存在才插入
  （记 `created`），同批重试不新增；内容未变记 `unchanged`。

## 6. 补正 API（`routes/intake.py`，权限 `analyst/admin`）

- `POST /api/intake/batches`：提交一批采集记录（`batch_no`、`agency_code`、`items[]`），
  幂等 upsert + 分诊 + 留痕，返回三类计数；
- `GET /api/intake/batches`：批次台账（谁被拦、各状态数量、重试链）；
- `POST /api/listings/{id}/corrections`：单条补正（字段级 patch），服务端重新归一与分诊，
  校验失败返回 422 且 **不修改原记录**（独立事务 + 留痕 `rejected`）；
- `POST /api/intake/batches/{batch_no}/retry`：补正后整批重试，复用批次号或挂 `retry_of`，
  同样幂等；
- `POST /api/listings/{id}/withdraw`：撤回挂牌（置 `withdrawn_at`、`status=off_market`），
  下次重算自动出簇；撤回不删记录。

所有写操作走 `audit_service` 留痕（`intake.ingest / intake.correct / intake.withdraw`）。

## 7. 查询与导出

- `GET /api/listings` 增加 `stage` 过滤；序列化返回 `stage / stage_label / defect_flags /
  ingest_batch / can_merge / withdrawn_at`；
- 总览与中介覆盖增加三类计数与待补数；
- **银行清单**：
  - `GET /api/exports/bank-book.csv`（新）：只导出在售、完整、已入簇记录所属的簇，
    每个簇一行；首行为口径元数据（覆盖中介数/挂牌区间、生成时间、待补数量、排除规则），
    保证不出现 incomplete / invalid / off_market 记录；
  - 原 `clusters.csv` 增加覆盖范围与待补数量说明行，并同样剔除未完成/已撤回成员；
  - `listings.csv` 增加 `采集分诊 / 缺项 / 批次 / 撤回时间` 列（全量留档导出，供内部核对，
    与银行清单区分）。

## 9. 测试策略（pytest，纯函数 + sqlite 服务层）

- 分诊规则：完整/待补（价格面议、面积待核实）/不合规（越界面积、缺小区）；
- 流水线：待补记录不入簇、不串户型；补正后重算重新入列，既有簇键与 golden 不变；
- 批次幂等：同批两次提交 created 不增长，未变化记 unchanged；
- 补正失败不丢记录、留 rejected 痕迹；撤回后出簇且银行清单不可见；
- 银行清单：无 incomplete/invalid/off_market，含覆盖范围与待补数量元数据；
- 既有 55 个测试全部保持通过，seed 口径（386 簇 / 6 风险簇 / 6 复核单）不变。
